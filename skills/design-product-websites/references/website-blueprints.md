# Product website blueprints

| Visitor need | Pattern | Put in the section |
| --- | --- | --- |
| Understand an unfamiliar offer | Hero with evidence | Outcome-led headline, audience cue if needed, primary CTA, product evidence |
| Compare sibling tools | Product-suite showcase | Consistent title, use case, preview, proof points, and named destination per card |
| Browse one platform's capabilities | Feature grid | Self-contained capability cards with a distinct illustration and consistent action |
| Follow a workflow | Scroll-linked or manually stepped story | One step per heading, explicit progress and controls, a stable preview slot |
| Resolve a buying question | Pricing and FAQs | Billing period, included limits, objections, and terms next to the decision |

## Sketch two routes through the page

- A visitor who already understands the offer can take the primary action from the hero.
- A visitor deciding between products can scan the cards, choose one, and arrive at a detail route with the same product name and promise.
- Give each sibling equal visual space unless there is a real reason to prioritize one. Use accent differences to help orientation and text to identify each option.
- Put a working preview in a disclosure when it adds detail. Keep the product CTA outside that disclosure if it has a separate destination.
- Plan copy for long translated strings. Confirm the page sequence still reads with a static poster and at single-column widths.

Example brief: design a homepage for three fictional studio tools. The hero explains the suite, the cards compare planning, routing and reporting, and each preview shows one characteristic UI state. Finish with one action that matches the conversion goal.
